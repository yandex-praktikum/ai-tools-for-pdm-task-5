# Спецификация RAG-помощника «Листка»

## Назначение и данные

Локальная система поиска по демонстрационным регламентам поддержки. Корпус содержит docs/delivery-policy.md, docs/refund-process.md и docs/quality-review.md. inventory.csv задаёт ID, происхождение, владельца, версию, дату, разрешение и решение о включении.

Индексируются только строки include с permission=allowed и sensitivity=synthetic. Пути должны находиться внутри docs; документы имеют уникальные ID и корректный YAML frontmatter. Дубликаты и несовпадение метаданных отклоняются.

## Технический профиль

- Python 3.13; Windows x64 либо macOS Apple Silicon arm64; вычисления на CPU.
- sentence-transformers 5.1.2, ChromaDB 1.3.5, PyTorch 2.8.0; остальные версии в requirements.
- Локальная модель intfloat/multilingual-e5-base, папка models/multilingual-e5-base.
- Размерность 768, normalize_embeddings=True.
- Документ: passage: + название + текст фрагмента. Вопрос: query: + вопрос.
- Unicode NFC и нормализация пробелов для эмбеддингов; исходный текст сохраняется дословно.
- Структурные фрагменты: введение и H2, overlap=0; лимит 384 токена с названием, префиксом и спецтокенами. Длинные разделы делятся без потери текста.
- Лимит вопроса — 512 токенов с префиксом и спецтокенами; превышение отклоняется.
- Chroma PersistentClient: .rag_store, коллекция listok-e5-demo, cosine, embedding_function=None, явные векторы.
- top_k по умолчанию 8, не больше числа фрагментов коллекции.

## Контракты

prepare-model скачивает десять файлов модели и проверяет загрузку. index и ask используют только локальную модель.

index сохраняет manifest с профилем и хешами инвентаря, документов, модели и фрагментов. Новый процесс читает ранее сохранённый индекс. Изменение этих данных требует нового index.

ask и retrieve выполняют одинаковый поиск. Результат содержит status=retrieval_only, query_id, index_id, question, top_k, hits, context, context_chunk_ids и retrieval_trace_path. Hit содержит rank, chunk_id, text, metadata и distance. Метаданные включают ID документа, источник, раздел, версию, владельца, диапазон строк и хеши.

ИИ проходит полный маршрут по rag-policy.md: новый поиск, чтение hits, ответ, сохранение raw, finalize, показ результата. Raw содержит ровно answer, citations и decision. Citation содержит document_id, chunk_id и дословную quote. При достаточном контексте decision=answer и есть хотя бы одна ссылка; при недостатке данных после успешного поиска decision=insufficient_context и ссылок нет.

finalize сверяет структуру, актуальность индекса, сохранённые hits с коллекцией и manifest, исходную историю поиска, пару document_id/chunk_id и цитату. Успех сохраняет result, trace и citation-map с уникальным capture_id. Ошибка возвращает ненулевой код завершения без успешного result. Смысловая поддержка утверждений оценивается отдельно.

## Эксплуатация

README содержит установку и команды; AGENTS.md — помощь с установкой и обслуживанием; rag-policy.md — обработку вопросов. Результаты и паспорт среды создаются в evidence. Переносимые файлы используют относительные пути; окружения, модель, индекс и кеши не входят в публикацию.
