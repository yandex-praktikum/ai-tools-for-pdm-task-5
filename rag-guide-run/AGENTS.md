# AGENTS.md — работа с проектом «Листок»

## Что это за проект

Локальный поиск по трём демонстрационным регламентам доставки. Пакет `rag_demo` загружает документы из `docs/` через `inventory.csv`, строит E5-эмбеддинги на CPU, сохраняет индекс Chroma и возвращает найденные фрагменты. ИИ отвечает по этим фрагментам и проверяет цитаты командой `finalize`.

## Что прочитать

- Для установки — README, раздел своей ОС и соответствующий requirements-файл.
- Для изменений поведения — `spec.md` и нужный модуль `rag_demo/`.
- Перед ответами о регламентах — `rag-policy.md`.

Читай только необходимые файлы. Не загружай весь код, модель, кеши или прошлые результаты в чат для каждого вопроса.

## Установка и первый запуск

1. Работай из корня этого проекта. Проверь ОС, архитектуру, Python 3.13 и доступ к терминалу/файлам. Поддерживаемые конфигурации: Windows x64 и macOS Apple Silicon arm64.
2. Найди подходящее окружение в проекте. Если его нет, создай `.venv` по README. Не удаляй существующую среду; при необходимости выбери другое имя и используй его во всех командах.
3. Установи `requirements-windows.txt` или `requirements-macos.txt` через Python выбранного окружения. Выполни `pip check` и проверь фактические версии и архитектуру.
4. Если нет десяти файлов в `models/multilingual-e5-base/`, выполни `prepare-model`. Для полной готовой модели загрузка повторно не нужна.
5. Выполни `validate-docs`. Для исходного корпуса ожидаются три документа.
6. Если индекс отсутствует или устарел, выполни `index`. Готовый актуальный индекс используй повторно.
7. Выполни новый `ask` по вопросу пользователя либо первому вопросу из README. Прочитай результат, проверь вопрос, `status: retrieval_only` и найденные фрагменты.
8. Покажи пользователю фактический результат установки и поиска. Не объявляй команды выполненными без реального запуска; технические ошибки объясняй по выводу.

Обычные интерпретаторы: `.\.venv\Scripts\python.exe` на Windows и `.venv/bin/python` на macOS. Активация окружения не требуется. Для ответов дальше используй полный маршрут из `rag-policy.md`.

## Правила изменений

- Перед изменениями кратко назови файлы и ожидаемый результат.
- Сохраняй исходные формулировки документов и дословный текст цитат.
- Не зашивай ответы, ID источников и решение в обработчики вопросов.
- Индексируй только разрешённые строки `include` из `inventory.csv`.
- Используй одинаковый профиль модели для документов и запросов.
- При изменении корпуса или профиля пересоздай индекс и выполни новый поиск.
- Сохраняй JSON в UTF-8; stdout — результат, stderr — диагностика.
- Не записывай личные абсолютные пути в переносимую документацию или паспорт среды.
- Запускай проверки, соответствующие изменению; сообщай фактический результат.
- Не включай в публикацию окружения, модели, индекс, кеши и `evidence/`.
