# Спецификация локального помощника «Листка»

## Назначение и корпус

Проект выполняет семантический поиск по семи документам о самовывозе и программе лояльности. Состав и разрешение на включение заданы в `inventory.csv`. Включаются только строки `permission=allowed`, `sensitivity=synthetic`, `status=include`. Метаданные документа проверяются по инвентарю.

Документы содержат `id`, `title`, `version`, `updated`, `owner`, `access` и необязательный `source_status=current|superseded`. Отсутствующее значение означает `current`. Статус строки CSV и актуальность источника имеют разное назначение. Текущий корпус даёт семь документов и 19 фрагментов.

## Модель и индекс

Python 3.13, CPU, `intfloat/multilingual-e5-base`, размерность 768, нормализованные векторы. Для документов применяется `passage: `, для вопросов — `query: `. Unicode NFC и нормализация пробелов относятся только к эмбеддингам; текст цитат сохраняется дословно. Структурное разбиение по введению и H2, лимит фрагмента 384 токена с префиксом и названием, перекрытие 0, вопрос до 512 токенов без усечения.

Chroma хранится в `.rag_store/`, коллекция `listok-pickup-demo`, метрика cosine, явные векторы, `embedding_function=None`. Профиль: `top_k=8`, `retrieval_threshold=0.20`, `authorization_probe_distance=0.35`. Индекс содержит идентификатор, хеши корпуса и модели, профиль и метаданные каждого фрагмента. Изменение корпуса, модели или профиля требует индексации. Изменение политики требует нового запроса, но не перестройки неизменного индекса.

## Доступ и правила ответа

Роль customer использует public; support — public/staff; manager — все три уровня. Роль задаётся локально и не является аутентификацией человека. В активной версии v2 включён `filter_current_sources=true`. Запрос к Chroma учитывает роль и актуальность источников до отбора `top_k`. Диагностика недоступного контекста не запрашивает закрытые тексты.

`policy show` возвращает параметры, версию, SHA-256 политики, путь и SHA-256 системных правил. Допустимые решения v2: `answer`, `clarify`, `refuse`, `escalate`. Правила генерации описаны в `behavior/system-v2.md` и `rag-policy.md`.

## Повторное использование поиска

Границы доступа действуют для роли каждого текущего обращения независимо от способа получения фрагментов. Сохранённый результат не должен расширять доступ пользователя.

По умолчанию `ask` и `retrieve` сохраняют результаты в `.query_cache/`. Повторный запрос с теми же условиями может использовать сохранённые фрагменты вместо вычисления вектора и обращения к поиску. Смена вопроса, `top_k`, индекса, политики, системных правил, профиля или файлов модели создаёт отдельную запись. `--no-cache` выполняет поиск без чтения и заполнения этого хранилища. `cache status` показывает число записей; `cache clear` удаляет записи, сохраняя `evidence/`.

Повторное использование не сохраняет готовый ответ. Каждый вызов создаёт новый `query_id`, результат и историю поиска. ИИ составляет новый исходный ответ, а `finalize` создаёт новый `capture_id`. Старые файлы не перезаписываются. Сохранённые результаты содержат хеш данных и исходный идентификатор запроса; изменение записи без соответствующего хеша отклоняется.

Объект `search_execution` сохраняется в retrieval, истории поиска и итоговой истории ответа. Его поля: `mode=fresh_search|cached_results`, `cache_enabled`, `cache_key`, `cache_path`, `origin_query_id`, `saved_at`, `search_elapsed_ms`. У поиска без кеша поля key/path/saved_at равны null. Время относится к получению результата после проверки индекса; оно не включает генерацию ответа и `finalize`.

## Поиск, ответ и доказательства

`ask` / `retrieve` возвращают `status=retrieval_only`, `question`, `role`, `query_id`, `index_id`, `top_k`, `policy`, `hits`, `context`, `context_chunk_ids`, `context_state`, `filtering`, `search_execution`, `retrieval_trace_path`. У фрагмента: `rank`, `chunk_id`, `text`, `metadata`, `distance`. Состояния контекста: available, empty, forbidden. Ошибка команды не означает пустой контекст.

Исходный ответ имеет ровно три поля: `answer`, `citations`, `decision`. Цитата содержит `document_id`, `chunk_id`, `quote`; quote — непустая дословная подстрока указанного фрагмента. Для `answer` нужна цитата; `refuse` не имеет цитат; empty/forbidden допускают только refuse. Уточнение и обозначение необходимости проверки человеком оцениваются по смыслу.

`finalize` проверяет структуру, исходную историю, индекс, профиль, хеши корпуса и модели, роль, актуальность политики и источников, разрешённые фрагменты, пары document_id/chunk_id и точность quote. Успех создаёт новые result, историю поиска и ответа и citation-map. Ошибка возвращает ненулевой код без успешного result. История сохранена под техническими именами `retrieval_trace_path` и `trace_path`; JSON-поля и имена файлов стабильны.

Техническая проверка не доказывает правильность и полноту ответа. Поиск, ответ, цитаты и безопасность оцениваются отдельно по заранее заданным требованиям. При проверке нескольких вариантов сохраняются последовательность запросов, состояние хранилища, роль и фактический режим получения фрагментов.

## Формат проверок

`eval/inputs.json` содержит массив `inputs` из 12 исходных обращений с полями `case_id`, `question`, `role`. Это входные данные без ответов, ожиданий и оценок. В записях ожиданий значение `role` переносится в `user_role`; вопросы и идентификаторы сохраняются. Дополнительные проверки записываются отдельно.

Для сравнения режимов исходные вопросы выполняются с `--no-cache`, затем с повторным использованием результатов. Контрольный и основной прогоны получают отдельные файлы. Условия повторных обращений, порядок ролей и состояние хранилища сохраняются; результат одного режима не выдаётся за доказательство другого.

`eval/eval-case.schema.json` задаёт формат одного кейса из 11 полей: `case_id`, `question`, `user_role`, `expected_source`, `forbidden_source`, `expected_decision`, `retrieval_criteria`, `generation_criteria`, `citation_criteria`, `safety_criteria`, `criticality`. Источники — ID документа или null; критерии — текст; критичность — low/medium/high.

Для каждого выполненного запроса сохраняются результат поиска, исходный ответ, результат `finalize` либо его ошибка и оценка четырёх направлений с объяснениями. Сводка отдельно показывает критические нарушения, неоднозначные результаты и ограничения проверки. История одного запроса не выдаётся за новый прогон.
