# plan.md — Поиск по документам сервиса «Кадр», 5.2.5

Требования записаны в `spec.md`, исходники — в `docs/`. Выполнять по одному этапу с помощью ИИ. Отмечать пункт после фактической проверки результата.

## 1. Подготовить документы

- [ ] Прочитать 12 файлов и создать `inventory.csv` по `spec.md`.
- [ ] Отметить актуальные документы, исключить повторную копию и старую версию. Сохранить причины в инвентаре, состав — в `corpus-passport.md`.
- [ ] Проверить решения по исходным файлам. Не менять их содержание.

## 2. Создать основу проекта

- [ ] Создать пакет `rag_demo`, файл зависимостей и `.gitignore`.
- [ ] Подготовить `.venv`, установить библиотеки и выполнить `pip check`.
- [ ] Загрузить файлы E5 в `models/multilingual-e5-base`, проверить загрузку на CPU и размерность 768.
- [ ] Записать команды запуска для своей ОС в `README.md`.

## 3. Подготовить фрагменты

- [ ] Реализовать чтение только включённых документов и разбиение по введению и H2-разделам.
- [ ] Сохранить дословный текст, идентификаторы и метаданные в `evidence/chunks.json`.
- [ ] Сверить два фрагмента с исходниками: условия отмены и сроки возврата должны сохраниться целиком.

## 4. Построить индекс

- [ ] Реализовать и запустить `index` с настройками из `spec.md`.
- [ ] Проверить количество и пути включённых документов в индексе. Дубликат и старая версия должны остаться вне него.
- [ ] Сохранить `.rag_store/manifest.json` автоматически при индексации.

## 5. Проверить поиск

- [ ] Реализовать `retrieve` и `ask`, проверить сохранение полного JSON.
- [ ] Выполнить три запроса из таблицы и сохранить каждый результат в отдельный файл.
- [ ] Прочитать найденные фрагменты и сверить их с исходниками. Проверить, есть ли сведения для ответа, включая вопрос без данных.
- [ ] Завершить процесс и повторить один запрос в новом процессе, используя сохранённый индекс.

| Вопрос | Файл результата |

| За сколько минут до бронирования можно войти в студию? | `evidence/retrieval-access.json` |
