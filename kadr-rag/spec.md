# spec.md — RAG-помощник сервиса «Кадр»

## Задача

Создать локальный помощник по правилам бронирования фотостудий. В 5.2.5 Python находит фрагменты документов. В 5.2.6 модель текущего чата ИИ отвечает по этим фрагментам и указывает источники.

## Документы

Все исходники лежат в `docs/`. Метаданные в начале файла содержат `id`, `title`, `owner`, `version`, `updated`, `permission`, `sensitivity` и `inclusion_status`.

Создать `inventory.csv`: одна строка на каждый исходный файл, столбцы `path,id,title,owner,version,updated,status,reason`. Значения брать из документов. В `status` записать `include` или `exclude`, в `reason` — основание решения.

Включать только актуальные документы с `permission: allowed`, `sensitivity: synthetic` и `inclusion_status: approved`. Из полных дубликатов оставлять одну копию и объяснять выбор. При наличии новой версии исключать старую. Не удалять и не переписывать исходники. У включённых документов должны быть уникальные `id`; исключённая копия может иметь тот же `id`.

В `corpus-passport.md` кратко записать назначение базы, состав включённых файлов и причины исключений. Список разрешённых документов определяется строками `include` в инвентаре.

## Технические настройки

| Параметр | Значение |
| --- | --- |
| Среда | Python 3.13, CPU, виртуальное окружение `.venv` |
| Библиотеки | `sentence-transformers==5.1.2`, `chromadb==1.3.5` |
| Модель | `intfloat/multilingual-e5-base` |
| Локальные файлы модели | `models/multilingual-e5-base` |
| Эмбеддинги | 768 измерений, `normalize_embeddings=True` |
| Текст документа для модели | `passage: ` + название + текст фрагмента |
| Текст вопроса для модели | `query: ` + вопрос |
| Разбиение | Введение и разделы H2, без перекрытия |
| Размер фрагмента | До 384 токенов, включая префикс, название и спецтокены |
| Хранилище | ChromaDB `PersistentClient`, `.rag_store` |
| Коллекция | `kadr-e5-demo`, метрика `cosine` |
| Поиск | `top_k=8`, готовые векторы, `embedding_function=None` |

Документы и вопросы кодируются одной локальной моделью. Для эмбеддингов применять Unicode NFC и одинаковую нормализацию пробелов. Для чтения и цитирования сохранять исходный текст дословно. Длинные разделы делить по границам текста, без скрытого обрезания. Вопросы длиннее 512 токенов с префиксом и спецтокенами отклонять с понятным сообщением.

Модель загрузить с [карточки multilingual-e5-base](https://huggingface.co/intfloat/multilingual-e5-base). Сохранить файлы `config.json`, `model.safetensors`, `modules.json`, `sentence_bert_config.json`, `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json`, `sentencepiece.bpe.model`, `README.md` и `1_Pooling/config.json`. Можно скачать их вместе с ИИ, как в 5.2.3. При создании окружения использовать совместимые зависимости и CPU-версию PyTorch для своей ОС, затем выполнить `pip check`.

## Код и команды первой части

Создать пакет `rag_demo`, файл зависимостей, `.gitignore` и инструкции запуска в `README.md`. В `.gitignore` добавить `.venv`, `models`, `.cache`, `.rag_store` и `evidence`.

- `python -m rag_demo index` читает инвентарь, обрабатывает только включённые файлы, создаёт фрагменты и индекс. Сохраняет `evidence/chunks.json` с текстом и метаданными. Выводит число документов и фрагментов.
- `python -m rag_demo retrieve --question "..." --output evidence/retrieval.json` выполняет поиск и сохраняет полный JSON с тем же содержимым, которое выведено в терминал.
- `python -m rag_demo ask` принимает те же аргументы и выполняет тот же поиск.

Команды запускать интерпретатором `.venv` из корня проекта. В `README.md` указать фактический путь для ОС пользователя. Повторный `index` заменяет только коллекцию этого проекта и убирает старые фрагменты.

JSON поиска содержит `status: retrieval_only`, `question`, `query_id`, `index_id`, `top_k`, `hits`, `context` и `context_chunk_ids`. Каждый элемент `hits` содержит `rank`, `chunk_id`, исходный `text`, `distance` и `metadata`. Метаданные: `document_id`, `title`, `source_path`, `section`, `version`, `updated`, `owner`. Идентификаторы фрагментов должны быть устойчивыми при неизменных документах и разбиении.

В `.rag_store/manifest.json` автоматически сохранить `index_id`, хеш инвентаря, пути и хеши включённых файлов, настройки модели и разбиения. Перед поиском проверять актуальность индекса; при изменениях попросить повторить `index`. Фактические версии зависимостей записать в `README.md`.

## Продолжение в 5.2.6

Добавить `rag-policy.md` и команду `finalize --retrieval ... --answer-file ...`. ИИ формирует JSON с `answer`, `citations` и `decision`. Каждая ссылка содержит `document_id`, `chunk_id` и дословную `quote` из текущего найденного фрагмента.

`finalize` проверяет актуальность индекса, принадлежность ссылок текущему поиску и дословность цитат. Сохраняет ответ, карту источников и общий след поиска и ответа в `evidence/`. При достаточных сведениях `decision` равно `answer`, при недостаточных — `insufficient_context`, а список ссылок пустой. Подробнее этот этап описан в продолжении плана для 5.2.6.

Ответ создаёт ИИ текущего чата. Отдельный генеративный API, ключи и веб-интерфейс для этой работы не требуются.
